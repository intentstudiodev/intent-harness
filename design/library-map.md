# library-map

1. Read the design library card (tech stack) if one exists: base, stage, where it lives, profile.
2. For each component the scope needs: `as is` (the library has it) · `adjust` (close, say what differs) · `new` (nothing fits, say why). Default is `as is`.
3. Where the library has a component and the design wants a new one, that is a push back.
4. The map goes into the brief; `new` items become open questions if the user has not decided them.
