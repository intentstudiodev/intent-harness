# map-existing

Project status `Live` brings you here (`knowledge/start-project.md`, Which start). The product exists whether or not anyone wrote it down; the cards describe what is, not what should be. Run `research/reverse-engineer.md` with purpose `ours`, under these four rules:

1. **Nothing invented.** A card only for what the code, the running product, the designs or the data show. No screen, flow, rule, structure or component that is not there. Something that looks missing is not a card; it is one line in `sandbox/ideas.md`, and only if the owner asked for ideas at all.
2. **Found, not decided.** Status from evidence; every card's Source link points at the code path, the screenshot or the recording in `inputs/` (`inputs/links.md` for a repository); the card carries `as found` until the owner confirms the area, area by area, at a checkpoint.
3. **Whys asked, not guessed.** A why the code, a comment or a document states → `[likely]` with its Source. Otherwise the why stays `—` and the guess lives inside the question: `[ask: why does the deposit exist? our guess: damage cover]`. No `[assumed]` why in this start. The owner answers in batches per area (ask-questions): "is this still true?", "does this still matter?".
4. **No suggestions.** No "this flow could be shorter", no proposed IA, no better name. Map, list the contradictions — code versus docs, docs versus owner, two places in the code that disagree — and stop at the depth the owner works at, saying what was not read.

**First deliverable.** The IA map as found; features, screens, flows and rules as found; tech cards from the repository (stack, libraries, the design system linked, never copied); the contradictions list; `intent-format open` as the question list. Then the owner picks the area to confirm first. The retro asks one thing: did anything get written that the product does not show?
