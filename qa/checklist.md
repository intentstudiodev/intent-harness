# QA checklist
- The why first; conditions second.
- Each condition: serves the why? If not → condition questioned, an open question.
- Beyond the conditions: the KB's edge cases for the scope; empty, error and slow states; the shell's navigation.
- Evidence per result: what was done, what was seen, where recorded.
- Separate: passed · failed · condition questioned · bugs beyond the spec.
- A build that matches the spec but not the purpose is a finding, not a pass.
